# Задание для AI-агента (Codex): Chunk-Forest v2 — лечение вырождения пула кандидатов

## 1. Контекст

Первый full-запуск `chunk_forest` дал 6.1472% по `.text` (random_walk_top1000 — 7.5013%), и в README зафиксирована причина: «средний пул ~20 уникальных путей на benchmark, вторая волна фактически не раскрылась». Код-ревью с воспроизведением подтвердило вырождение генератора (`src/llvm_ir/heuristics/translation_unit/chunk_forest.py`).

Репродукция (обязательна как регрессионный тест, см. раздел 7): 10 функций с общим ядром `[sroa, instcombine, simplifycfg, gvn]` и десятью разными хвостами (`[dse,adce]`, `[licm,instcombine]`, `[dse]`, `[adce]`, `[jump-threading,dse]`, `[sccp]`, `[early-cse,dse]`, `[tailcallelim]`, `[reassociate,adce]`, `[memcpyopt]`), дельты 1000, 950, …, 550. Результат текущего кода: inventory = 10 (2 mined + 2 macro + 6 single), 19 рёбер, **41 уникальный путь из 100 000 блужданий**.

Цепочка причин:
1. Замыкание схлопывает все ядра в 1–2 аттрактора → mined-чанков почти нет, `top_chunks=30` не заполняется.
2. Одиночки добавляются только до `min_inventory=10` → алфавит блуждания ~10 нод.
3. Рёбра требуют, чтобы вхождение B начиналось через 0–2 pass-а ПОСЛЕ КОНЦА вхождения A — пересекающиеся вхождения (типичный случай для чанков из замыкания) рёбер не дают.
4. Тупик завершает путь; рестартов нет → большинство из 100k блужданий — дубликаты.
5. Следствие: пул < путей одной волны, волна 2 получает пустой выбор.

Правила прежние: регрессионный тест на каждый пункт, существующие тесты зелёные (кроме явно переписываемых), ключи отчёта только добавляются, без зависимостей, LLVM в тестах не вызывается. Урок про единицы измерения (mined-веса ≠ TU-байты) остаётся в силе.

---

## 2. P1 — алфавит: одиночки всегда, n-граммные корзины в майнинге

1. **Одиночки всегда.** Заменить логику `min_inventory` на явный параметр `--singles N` (default 12): top-N одиночных pass-ов (текущее ранжирование `_single_chunks`) добавляются в инвентарь ВСЕГДА, независимо от числа mined/macro. `min_inventory` удалить из `ChunkInventoryConfig` (конфиг — внутренний, обратная совместимость CLI не нарушается, т.к. такого флага не было).
2. **Корзины n-грамм.** После отбора замкнутых чанков дополнить инвентарь top сырыми n-граммами по корзинам длины: top `--ngrams-per-bucket` (default 5) n-грамм с `support >= min_support` для каждой длины 2..`ngram_max`, исключая те, что являются смежной подпоследовательностью уже взятого чанка той же или большей длины с тем же или большим весом. Kind для них — `"mined"`. Общий cap `top_chunks` сохраняется (сортировка прежняя).
3. В `chunk_kind_counts` ничего не менять; в строку отчёта добавить `inventory_size`.

Тест: на репродукции inventory ≥ 18 (одиночек 12 + mined-корзины), причём среди mined есть хотя бы одна n-грамма, не являющаяся подпоследовательностью аттрактора (например, биграмма из хвостов вроде `(gvn, dse)`).

## 3. P2 — рёбра: сшивка с наложением и fallback из order-графа

1. **Сшивка (splice).** Разрешить переход A→B при наложении: если суффикс `A.passes` длины k ≥ 1 совпадает с префиксом `B.passes` (брать максимальный такой k < len(B)), при конкатенации добавлять только `B.passes[k:]`. Ребро-сшивка добавляется в граф чанков с весом = Σ Δ функций, в которых соответствующая объединённая цепочка `A + B[k:]` встречается как смежная подпоследовательность (support-семантика); если объединённая цепочка не встречается ни в одной функции — сшивка легальна, но с малым весом `splice_epsilon × min(weight(A), weight(B))`, `--splice-epsilon` default 0.05.
2. **Fallback-рёбра из pass-level order-графа.** Для пар чанков без существующего ребра и без сшивки: если в `PassOrderGraph.edge_counts` есть ребро `(last(A), first(B))` с весом > 0 — добавить glue-ребро с весом `glue_scale × вес_ребра`, где `glue_scale = (медиана весов существующих chunk-рёбер) / (медиана весов задействованных pass-рёбер)`; при отсутствии существующих chunk-рёбер glue_scale = 1. Это нормировка, а не смешение единиц: оба веса остаются «функциональными», см. docstring.
3. **Декомпозиция при сшивке**: `ChunkRef` для B должен честно указывать start/end по фактически добавленным pass-ам; флаг partial — как раньше. Маргинал чанка B в credit assignment считается по его фактическому интервалу — проверить, что evaluator не предполагает `end - start == len(chunk.passes)` (если предполагает — поправить).
4. Не допускать сшивку, при которой добавляется 0 pass-ов (B целиком вложен в хвост A).

Тест: чанки `(sroa, instcombine, simplifycfg, gvn)` и `(simplifycfg, gvn, dse)` сшиваются в путь `sroa, instcombine, simplifycfg, gvn, dse` с корректной декомпозицией (второй ChunkRef покрывает только `dse`); fallback-ребро возникает между чанками, чьи границы связаны в order-графе, и его вес отнормирован.

## 4. P3 — блуждание: телепорт и рестарты

1. **Телепорт.** Параметр `--teleport 0.15`: на каждом шаге с вероятностью teleport следующий чанк выбирается не по рёбрам, а взвешенно по `start_weights ∪ глобальные веса` среди неиспользованных чанков (объединить в один словарь: вес чанка = start_weight или, при отсутствии, `chunk.weight`).
2. **Рестарт в тупике.** Если исходящих рёбер нет, а до `max_length` остаётся ≥ 1 pass — выполнять телепорт безусловно (а не завершать путь). Завершение пути — только по `max_length` или когда неиспользованных чанков не осталось.
3. **Стартовые веса.** Чанки, не встречающиеся на позициях 0–1 ни в одной функции, получают стартовый вес `start_floor × chunk.weight`, `--start-floor` default 0.1 — чтобы ни один чанк не был недостижим как старт.
4. **Ранняя остановка генерации** (эффективность): если за последние `--walk-stall 20000` итераций не появилось ни одного нового уникального пути — прекратить блуждания. В строку отчёта: `walks_executed`.
5. Детерминизм по seed сохраняется (все взвешенные выборы — через существующий `_weighted_choice` с отсортированными ключами).

Тест-якорь (регрессия на вырождение): репродукция из раздела 1 после P1–P3 даёт `pool_unique_paths >= 5000` при 100k блужданий (порог с запасом; зафиксировать фактическое значение в комментарии теста). Отдельный тест: телепорт = 0 и start_floor = 0 и splice выключен → поведение совпадает со старым на маленьком графе (ветки спят).

## 5. P4 — гарантии для волны 2

1. Если после волны 1 непросмотренная часть пула меньше `paths/waves` — это сигнал деградации: в строку отчёта писать `wave2_pool_available`; при нуле волна 2 пропускается с флагом `wave2_skipped: true` (сейчас она молча выбирает из пустоты).
2. В `select_paths` при исчерпании кандидатов с положительным gain продолжать выбор по наименьшему штрафу (как сейчас через max по gain — проверить, что отрицательный gain не прерывает отбор раньше времени; если прерывает — поправить и покрыть тестом).

## 7. Тесты (сводно)

1. Якорь-репродукция: данные из раздела 1, проверки — inventory ≥ 18, наличие не-аттракторной n-граммы, `pool_unique_paths >= 5000`, в пуле существует путь, содержащий pass-ы минимум из 3 разных чанков.
2. Сшивка: корректная конкатенация и декомпозиция; запрет нулевой сшивки; нормировка glue-веса.
3. Телепорт: при seed-детерминизме два запуска идентичны; тупик с остатком длины продолжает путь.
4. Спящие ветки: при выключенных новых параметрах старое поведение воспроизводится.
5. Волна 2: при пуле > paths/waves волна 2 выбирает непустое множество; `wave2_skipped` выставляется только при реально пустом остатке.
6. Существующие тесты chunk-forest: переписать только те, что фиксируют `min_inventory`-логику и старую семантику тупика; перечислить их в сообщении коммита.

## 8. Критерии приёмки

1. Полный тест-сьют зелёный; якорь-репродукция падает на HEAD до фикса (сейчас пул = 41).
2. Генератор на репродукции отрабатывает за разумное время (< 30 с на 100k блужданий с учётом ранней остановки).
3. Отчёт совместим; новые поля: `inventory_size`, `walks_executed`, `wave2_pool_available`, `wave2_skipped`.
4. Коммиты: P1, P2, P3, P4 — отдельно, сообщения на английском (`fix: always include single-pass chunks and ngram buckets`, `feat: overlap splicing and order-graph glue edges for chunk graph`, `feat: teleport restarts in chunk walks`, `fix: wave-2 pool guarantees`).

## 9. Что НЕ делать

- Не менять майнинг-замыкание по существу (аттракторы остаются; корзины — дополнение, не замена).
- Не менять субмодулярный отбор, auto_lambda, credit assignment и перенормировку волны 2 (кроме пункта 5.2 при необходимости).
- Не трогать evaluator-ы других эвристик и prefix cache.
- Не разрешать повторное использование одного чанка в пути (повторы pass-ов между разными чанками по-прежнему легальны и после сшивки станут чаще — этого достаточно).
- Не добавлять зависимости и многопроцессность.
